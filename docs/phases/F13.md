# F13 — macOS, written without a Mac

**Status: built blind in session 33 ([[D-463]]), measured only by CI's macOS runner; never run by a person on a Mac.** SPEC §19 keeps macOS out of v1 and this phase does not change that: v1 ships Windows and Linux. What this phase does is the part SPEC §19's closing paragraph says can be done without a Mac on a desk — the code, compiled and exercised by GitHub's macOS runner — so that when a Mac and a card are in hand, what is left is the small known part.

Every claim below is marked **measured on CI** (with the job that measures it), **reasoned** (written from documentation or from the Linux code it shares, not run), or **needs a Mac / a card / a person / the owner**.

---

## 1. The window host

AppKit owns the process's main thread. Go runs `main.main` on it only if the main goroutine is pinned there from the start, so `internal/ui` locks the thread in an `init` (darwin), and `ui.RunMain(f)` runs the program on a goroutine while the main thread runs `[NSApp run]`. `main` calls it on every platform; elsewhere it is `f()`. A process that never calls it (a test without its `TestMain`) gets `ErrNoMainLoop` from `NewWindow` rather than a hang.

The application is an **accessory** (`LSUIElement`, activation policy accessory): no Dock icon, no menu bar of its own — an agent in the status bar, as it is a tray agent elsewhere.

A window is an `NSWindow` holding a `WKWebView` subclass. The shape is the Linux host's, deliberately, so one set of pages serves both:

- **Assets** come from a `WKURLSchemeHandler` for `liro://`, resolved by the same `resolveAsset` as WebKitGTK's scheme (`assetscheme_unix.go`, renamed from `_linux` to be shared).
- **The page talks back** through `window.webkit.messageHandlers.liro` — the name `bridge.js` already uses on Linux, because both are WebKit. No page changes.
- **Navigation** off the window's own asset hosts is refused; a request for a second window gets none.
- **Dropped files** are taken by the view subclass from the pasteboard (file URLs only) before WebKit would navigate to them.
- **Eval** is `evaluateJavaScript:`, its result JSON-encoded as WebView2's and WebKitGTK's are; an exception or an unsupported value is `"null"`, as the `Window` interface documents.
- **Close from Go** is never reported as the person closing the window (`OnClosed` is the person's).
- Native dialogs: `NSAlert` for notices and warnings, `NSOpenPanel` for files and folders, `NSAlert` with an `NSSecureTextField` for a PIN, `NSStatusItem` with a menu rebuilt on each opening for the tray.

**Measured on CI** (`macos` job, `TestAMacWindowLoadsAPageAndCarriesMessagesBothWays`): a window opens, the origin page loads from the embedded assets, a payload lands, the page's `liroSend` reaches Go, a navigation off the assets is refused, the window resizes and navigates; the window is photographed (`screencapture`) into the job's `liro-macos` artifact. **Not measured anywhere:** a drop, the PIN dialog, the open panel, the status-bar menu — each needs a pointer or a keyboard.

## 2. The secret store — the Keychain

SPEC §6.4's macOS row. Device secrets are generic passwords in the person's login Keychain, service `liro-bridge`, account the secret's name, through `SecItemAdd`/`SecItemCopyMatching`/`SecItemDelete` — **not** the `security` command, whose items are bound to `/usr/bin/security`.

What binds an item to this program is its code signature, and **this program is not signed for macOS** (§6). The Keychain then identifies it by path and contents, so an updated binary is asked about the old items once. The data-protection keychain is not used: it needs an entitlement an unsigned program cannot have.

**Measured on CI** (`TestTheKeychainStoreRoundTrips`): store, read, replace, delete, absence — under a test service. **Needs a Mac and a person:** what the prompt looks like after an update.

## 3. PKCS#11

The Linux layer is the macOS layer: `module_unix.go`, `login_unix.go`, `slots_unix.go`, `probechild_unix.go` (renamed from `_linux`) build for `linux || (darwin && cgo)`. `dlopen` with `RTLD_NOW|RTLD_LOCAL` means the same on macOS; the code uses the header's own C types through cgo, so the compiler lays the structures out and there is no Go copy of them to be wrong (Windows has one, packed to one byte, which F11 had to measure).

Discovery (`discover_darwin.go`) looks for SafeSign's `libaetpkss.dylib` and OpenSC under `/usr/local/lib`, `/Library/OpenSC/lib`, `/opt/homebrew/lib` and `~/lib` — **reasoned, from the vendors' documentation as recalled; no path was read off an installed package.** A module elsewhere is reached by `pkcs11ModulePath`.

**Measured on CI** (`realmodule_unix_test.go`, against Homebrew's SoftHSM with one RSA key and its certificate, `build/macos/ci-softhsm.sh`): the module loads, its info and slots read, a login, a signature verified against the certificate's own key, a wrong PIN counted once, the compiler's layout. **Needs a card:** SafeSign on macOS with a Pošta card — the only Serbian middleware with a macOS build (SPEC §11.11).

Card presence through PC/SC (macOS has `PCSC.framework`) is **not built**: discovery and the module's own slot list are what the agent uses; the presence check is Windows' and Linux's.

## 5. Starting, links, autostart

- **A link** reaches a macOS application as an Apple Event (`kAEGetURL`), not in argv. The handler is installed before the loop runs, a link that arrives before Go asks is kept (`ui.SetURLHandler`), and it goes where `open-link`'s argument goes: checked, then left in the inbox for the agent's watcher (F14 §1). The scheme is declared in the bundle's `CFBundleURLTypes`; nothing registers it at run time. **Reasoned**, not run: needs LaunchServices.
- **A bundle launched with no arguments is the agent** (`launchArgs`): Finder and LaunchServices start it so, and an old `-psn_` argument is dropped.
- **Autostart** is a LaunchAgent, `~/Library/LaunchAgents/rs.liro.bridge.plist`: the bundle's binary with `tray`, at login, in the graphical session, never restarted (a person who chose Quit meant it). Written, not loaded with `launchctl` — the agent writing it is already running. **Measured** on every platform for its content (`launchagent_test.go`, linted by `plutil` on the runner); its effect at login **needs a Mac**.
- **Notifications** go through `osascript display notification` with the text as arguments, never as script. Attributed to Script Editor and impossible to withdraw, until the bundle is signed and can use `UNUserNotificationCenter`.

## 6. Packaging

`build/macos/build.sh <version> [outdir]` builds a universal (arm64 + x86_64) binary into `Liro Bridge.app`, writes `Info.plist` from `Info.plist.in`, makes `liro-bridge.icns` from the `.ico`'s own frames, and zips the bundle with `ditto`. CI uploads the zip.

**Not signed and not notarised.** Gatekeeper refuses an unsigned downloaded application at first launch; a person can open it from the context menu (Open) or with `xattr -dr com.apple.quarantine`, neither of which belongs in a guide for people who sign contracts. Signing needs an Apple Developer ID (a paid membership, the owner's), and notarisation needs it too. **The owner's decision** — as SPEC §15.1 left Windows' code signing.

The icon's 512 and 1024 sizes are scaled up from the 256 frame (the `.ico` has none larger) and will look soft in Finder at Retina sizes until `scripts/genicon` draws them.
