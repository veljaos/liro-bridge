# Phase F0 — Foundation

**Prerequisite reading:** `docs/SPEC.md`, in full. This phase implements several of its rules as automated checks. If you have not read it, stop and read it now.

**Goal of this phase:** produce an empty but correct project. Nothing signs anything yet. What must exist is the skeleton, the conventions, and the automated guardrails that will keep every later phase honest.

**Explicitly not in this phase:** certificates, PDF handling, cryptography, HTTP, UI. Do not create placeholder files for them. Do not write "TODO: implement signing". The repository at the end of F0 contains only what is listed below.

## 2. Configuration

**Package:** `internal/config`

### 2.1 Where configuration lives

| OS | Path |
|---|---|
| Windows | `%LOCALAPPDATA%\Liro\config.json` |
| macOS | `~/Library/Application Support/Liro/config.json` |
| Linux | `$XDG_CONFIG_HOME/liro/config.json`, falling back to `~/.config/liro/config.json` |

Resolve this through a function in `internal/platform`, not with string concatenation scattered around the code.

### 2.2 Shape

```go
// Config is the agent's persistent configuration. Every field has a usable
// zero-value default, so a missing or partial file is never an error.
type Config struct {
    // Locale is the interface language: "sr-Latn", "sr-Cyrl" or "en".
    Locale string `json:"locale"`

    // LogLevel is one of "debug", "info", "warn", "error".
    LogLevel string `json:"logLevel"`

    // PortRangeStart and PortRangeEnd bound the loopback listener search.
    PortRangeStart int `json:"portRangeStart"`
    PortRangeEnd   int `json:"portRangeEnd"`
}
```

Defaults: `Locale: "sr-Latn"`, `LogLevel: "info"`, `PortRangeStart: 17580`, `PortRangeEnd: 17590`.

### 2.3 Behaviour

- `Load()` reads the file, applies defaults for missing fields, validates, and returns a `Config`.
- A missing file is **not an error**. It returns defaults.
- A malformed file **is** an error, but a recoverable one: log a warning, return defaults, and do not overwrite the user's file. Silently replacing a file the user hand-edited is hostile.
- An invalid value (a locale of `"sr"`, a port outside 1024–65535) falls back to the default with a logged warning. A bare `"sr"` is specifically invalid — see SPEC §9.1.
- `Save()` writes atomically: write to a temporary file in the same directory, then rename. A crash mid-write must never leave a truncated config.

### 2.4 Tests

- Missing file returns defaults.
- Partial JSON (`{"locale":"en"}`) fills the rest with defaults.
- Malformed JSON returns defaults and an error, and does not touch the file on disk.
- `"sr"` is rejected and replaced with `"sr-Latn"`.
- Out-of-range port is replaced.
- `Save` followed by `Load` round-trips.

## 3. Logging

**Package:** `internal/config` (function `SetupLogging`) using the standard library `log/slog`. No third-party logging library.

### 3.1 Two destinations

1. **File**, JSON format, at the platform log directory (`%LOCALAPPDATA%\Liro\logs\bridge.log` on Windows and the equivalents elsewhere). This is the durable record.
2. **stderr**, human-readable text, only when the environment variable `LIRO_DEBUG=1` is set. This is for development.

### 3.2 Rules

- **Log lines are always English**, regardless of interface locale. Logs are read by developers, not users. This is SPEC §9.2.
- Rotation by size: 5 MB per file, 3 files retained. Implement it yourself — it is roughly 40 lines and avoids a dependency.
- **Never log:** JMBG, email addresses, personal names, file names, document contents, PINs, device secrets. This is SPEC §18.3 and it applies to the general log, not only the audit log.
- Certificate identification in logs uses the SHA-1 thumbprint, never the subject.

### 3.3 A redaction helper

Provide `func Redact(s string) string` which replaces the middle of a string with `…`, keeping at most 4 leading and 4 trailing characters. Use it whenever something borderline must appear. Test it.

## 4. Errors

**Package:** `internal/errs`

This implements SPEC §7. It exists in F0 so that every later phase has somewhere correct to put its error cases.

```go
// Code is a stable, machine-readable error identifier. Codes are never
// removed or repurposed; new situations get new codes.
type Code string

const (
    CodeNotPaired        Code = "NOT_PAIRED"
    CodeAuthFailed       Code = "AUTH_FAILED"
    CodeConsentDenied    Code = "CONSENT_DENIED"
    CodeConsentTimeout   Code = "CONSENT_TIMEOUT"
    CodeNoReader         Code = "NO_READER"
    CodeCardNotPresent   Code = "CARD_NOT_PRESENT"
    CodePINRequired      Code = "PIN_REQUIRED"
    CodePINIncorrect     Code = "PIN_INCORRECT"
    CodePINLocked        Code = "PIN_LOCKED"
    CodeCertNotFound     Code = "CERT_NOT_FOUND"
    CodeCertExpired      Code = "CERT_EXPIRED"
    CodeCertNotUsable    Code = "CERT_NOT_USABLE"
    CodeCertRevoked      Code = "CERT_REVOKED"
    CodeTSAUnavailable   Code = "TSA_UNAVAILABLE"
    CodeTSARejected      Code = "TSA_REJECTED"
    CodePDFInvalid       Code = "PDF_INVALID"
    CodePDFEncrypted     Code = "PDF_ENCRYPTED"
    CodeSignFailed       Code = "SIGN_FAILED"
    CodeVersionTooOld    Code = "VERSION_TOO_OLD"
    CodeInternal         Code = "INTERNAL"
)

// Error is the only error type that crosses an API boundary. It carries a
// code and optional structured details — never a human-readable message.
// Translation happens in the SDK or the UI, not here.
type Error struct {
    Code    Code           `json:"code"`
    Details map[string]any `json:"details,omitempty"`

    // cause is the internal error. It is never serialised and never sent
    // to a client; it exists for logging.
    cause error
}

func (e *Error) Error() string { ... }   // English, for logs only
func (e *Error) Unwrap() error { return e.cause }

func New(code Code, cause error) *Error
func WithDetails(code Code, cause error, details map[string]any) *Error
```

### 4.1 The serialisation test

Write a test that marshals an `Error` with a cause and asserts that **the cause does not appear in the JSON**. This is the test that stops someone helpfully adding a `Message` field in six months.

## 5. Internationalisation skeleton

**Package:** `internal/i18n`

Implements SPEC §9. In F0 this is a working mechanism with a handful of messages, not a full catalogue.

### 5.1 Structure

```
internal/i18n/
├── i18n.go
├── locales/
│   ├── sr-Latn.json
│   ├── sr-Cyrl.json
│   └── en.json
└── i18n_test.go
```

Catalogues are embedded with `//go:embed locales/*.json`.

### 5.2 Catalogue format

Flat key-value. Keys use dots and mirror error codes where they correspond.

```json
{
  "app.name": "Liro Bridge",
  "error.card_not_present": "Kartica nije u čitaču.",
  "error.no_reader": "Čitač kartica nije pronađen.",
  "error.internal": "Došlo je do neočekivane greške."
}
```

Create the same three keys plus `app.name` in all three files for F0. That is enough to prove the mechanism.

### 5.3 API

```go
// Catalogue resolves message keys for one locale.
type Catalogue struct{ ... }

// Load returns a catalogue for the requested locale. An unknown or empty
// locale falls back to sr-Latn. A bare "sr" is treated as invalid input
// and falls back — never silently resolved to Cyrillic (see SPEC §9.1).
func Load(locale string) *Catalogue

// T returns the message for key. A missing key falls back to the English
// catalogue and logs a warning. If the key is missing there too, T returns
// the key itself — visible in the UI, which is the point: it must be
// noticed, not hidden.
func (c *Catalogue) T(key string) string

// CodeKey maps an error code to its message key:
// CodeCardNotPresent -> "error.card_not_present"
func CodeKey(code errs.Code) string
```

### 5.4 The completeness test

Write a test that loads all three catalogues and asserts they have **identical key sets**. A key present in `en` but missing from `sr-Cyrl` fails the build. This is the only thing that keeps translations from rotting.

## 6. Linting and the dependency rule

### 6.1 golangci-lint

Commit `.golangci.yml`. Enable at minimum: `govet`, `staticcheck`, `errcheck`, `ineffassign`, `unused`, `misspell`, `gofmt`, `goimports`.

### 6.2 The dependency checker — write this yourself

**Location:** `scripts/checkdeps/main.go`

This enforces SPEC §4.2. Do not use a third-party import linter; the rule set is five lines long and must not stop working silently when a dependency changes.

It runs `go list -deps -json ./...` (or parses imports directly), builds the import graph, and fails with a non-zero exit code and a clear message if any of these hold:

```
internal/pades      imports  internal/api
internal/keysource  imports  internal/pades
internal/trust      imports  any internal/ package
internal/api        imports  internal/ui  or  internal/cli
internal/ui         imports  internal/api or  internal/cli
internal/cli        imports  internal/api or  internal/ui
any internal/       imports  cmd/
```

Output on violation must name the offending package, the forbidden import, and the SPEC section:

```
FORBIDDEN IMPORT
  internal/pades/cms imports internal/api
  Rule: the PDF engine must be usable without the HTTP server (SPEC §4.2 rule 1)
```

### 6.3 Test the checker

Add a test with a fabricated import graph containing a violation, asserting the checker detects it. A guardrail that has never been observed to fire is not a guardrail.

## 8. Continuous integration

**File:** `.github/workflows/ci.yml`

Runs on push and pull request. Steps:

1. Check out, set up Go (pinned version).
2. `gofmt -l .` — fails if anything is unformatted.
3. `go vet ./...`
4. `golangci-lint run`
5. `go run ./scripts/checkdeps`
6. `go test ./... -race -count=1`
7. Build for `windows/amd64`, `darwin/arm64`, `linux/amd64` — cross-compilation must work from day one, even though only Windows has an implementation. It is far cheaper to keep it working than to restore it in phase 12.

A red CI blocks the phase. There is no "we will fix the linter later".

## 9. `docs/decisions.md`

Create the file with the format from SPEC §17 and these entries, written properly with reasoning and rejected alternatives:

- **D-001** — Go as the implementation language. Why: single binary, no runtime, good systems access, cross-compilation. Rejected: .NET (runtime dependency), Rust (smaller talent pool for this project), Node (packaging and startup).
- **D-002** — Errors as codes, never messages. Why: one agent serves three interface languages and unknown third-party clients; translation belongs at the edge. Rejected: message plus code (invites clients to display our English text).
- **D-003** — The dependency rule is enforced by a checker we own, not by a linter plugin.
- **D-004** — `log/slog` and hand-written rotation rather than a logging library.
- **D-005** — Licence choice, with reasoning.

## 10. Traps in this phase

- **`gofmt` on Windows.** Line endings will fight you. Commit a `.gitattributes` with `* text=auto eol=lf` and make sure Go files are LF in the repository.
- **`%LOCALAPPDATA%` in tests.** Never touch the real user directory from a test. The path resolver must accept an override so tests use `t.TempDir()`.
- **Embedded files and paths.** `//go:embed locales/*.json` requires the files to exist at compile time. An empty directory with a `.gitkeep` will not satisfy it.
- **Cross-compilation and cgo.** Keep `CGO_ENABLED=0` for now. Phase 11 will change that for PKCS#11; until then, anything that would require cgo is out of place.
